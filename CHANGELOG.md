## 1.1.0 — 2026-10-02 (source implementation)

Additive profiles and working-knowledge tools; native content format remains 1.0.
This source version does not itself publish a release or migrate existing files.

- Optional structured/1 tuple, exact-text, local-reference and canonical named-role
  codecs over unchanged native Terms. Ordinary call arity remains significant.
- Optional notation/1 lowering and checked explicit printing, with bounded lexical
  prefix aliases, ground abbreviations and fixed arithmetic/1 spelling.
- Immutable working/1 record validation/indexing, whole-record reference-closed
  selection, and separate reverse-dependency review impact.
- Strict scir-change/1 requests and snapshot-guarded, all-or-nothing candidate
  construction. No in-place writes, persistence, execution or authorization.
- Explicit lower and knowledge check/select/affected/propose CLI commands; existing
  commands retain their syntax, output and exit behavior.
- Profile contracts, public API guidance, portable consumer reference and a runnable
  dual-notation example with independent native expected content.
- The implementation was delivered in five slices: structured codecs; working
  indexes and selection; guarded changes; optional notation; and integration.
- Native source-byte sentinels, generated and exhaustive finite law tests, a small
  separate Lean closure/tree model, cross-platform distribution checks and measured
  synthetic payload/workflow envelopes. These do not establish agent task quality.

## 1.0.0 — 2026-09-12

Initial release baseline with a stable 1.x contract.

- One ground Term constructor and ordered, duplicate-preserving documents.
- Separate patterns, structural queries, simultaneous substitution, and targeted edits.
- Snapshot-bound annotations, interpretation alternatives, and lossless forest transport.
- Optional application constraints: ordered diagnostics, form/vocabulary helpers,
  and documented dialect composition without changing the content format.
- Bounded parsing and validated transport; symbol names are never executed.
- Read-only CLI, including `--version` and `fmt --check`.
- CLI data and processing-error output uses UTF-8 bytes and LF independently of
  the terminal encoding and platform newline translation.
- Executable incident, correction, requirement, and correlated-ambiguity examples.
- Portable consumer and Markdown-migration skills, with independent human prose.
- Architecture, investigation, and argument examples with source checks and review-dependency closure.
  Mathematical limitations retain their premise dependencies, not just conclusions.
- Complete first-run setup for macOS/Linux and Windows, plus a fresh-project handoff fixture.
- Consumer preparation bounds runtime discovery and reads only task-relevant
  references; repeated checks require a relevant change or failure.
- Fixed-source dialect-chain example with cumulative checks, projections, and a blocked target.
- Project-owned SCIR requirement index with static source/test checks and a Markdown view.
- Query/occurrence knowledge maintained in SCIR, with exact specification/API
  views, executable examples, and stale-view checks.
- Format `1.0`, with fixed canonical-text, fingerprint, and transport test vectors.

Distribution: `symbolic-content-ir`. Python import and command: `scir`.
The [compatibility policy](SPEC.md#versioning-and-compatibility) defines what 1.0
commits to.
